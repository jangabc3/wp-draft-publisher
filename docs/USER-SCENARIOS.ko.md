# 사용자 시나리오

## 시나리오 1: 처음 설치한 사용자가 첫 임시글 만들기

**사용자:** WordPress 블로그를 운영하지만 코딩 경험은 없습니다.

**준비:** `install.cmd` 설치와 WordPress 브리지 활성화를 완료했습니다.

**요청 예시:**

```text
2026년 청년 월세 지원 조건과 신청 방법을 공식 자료로 조사해줘. 초보자가 그대로 따라 할 수 있는 글로 작성하고 이미지와 FAQ, SEO 설정까지 마친 뒤 워드프레스에 임시저장해줘.
```

**프로그램이 처리하는 작업:**

1. 연결 과정에서 감지한 사이트 정보와 사용자가 답한 주제·말투·독자층 프로필을 읽습니다.
2. 최신 공식 자료와 기존 사이트 글을 확인합니다.
3. 제목, 도입부, 본문, 표, FAQ, 출처를 구성합니다.
4. 대표 이미지와 본문 이미지를 준비하고 대체 텍스트를 지정합니다.
5. 카테고리, 태그, SEO 제목, 설명, 핵심 키워드를 설정합니다.
6. 저장할 사이트·카테고리·이미지 수·SEO·품질 결과를 읽기 전용 계획으로 먼저 확인합니다.
7. 계획과 요청이 일치하고 품질검사를 통과한 글만 WordPress 임시글로 저장합니다.
8. 서버에 저장된 내용을 다시 읽어 일치 여부를 검증합니다.

**사용자가 하는 일:** WordPress 미리보기에서 사실관계와 디자인을 확인한 뒤 직접 공개합니다.

## 시나리오 2: 내용만 먼저 검토하고 저장하기

**요청 예시:**

```text
해외여행 환전 수수료 줄이는 방법을 글로 준비해줘. 아직 워드프레스에는 저장하지 말고 품질검사 결과와 수정할 부분을 먼저 보여줘.
```

AI는 `quality-check`와 `preview-plan`을 사용해 저장 예정 내용과 문제점을 확인합니다. 사용자가 저장을 요청하기 전에는 WordPress를 변경하지 않습니다.

## 시나리오 3: 같은 주제의 임시글 보완하기

**요청 예시:**

```text
지난번에 만든 ETF 초보 가이드 임시글에 실제 계산 예시와 FAQ를 추가하고 다시 검사해줘. 같은 글을 갱신하고 새 글은 만들지 마.
```

같은 슬러그의 임시글을 찾아 갱신합니다. 공개된 글이 같은 슬러그를 사용하고 있다면 작업을 중단합니다. 수정 직전에 서버 스냅샷을 남깁니다.

## 시나리오 4: 사람이 편집 중인 글과 충돌하기

**상황:** 사용자가 WordPress 편집기에서 글을 수정한 사이 AI도 이전 내용을 기준으로 저장하려고 합니다.

프로그램은 `modified_gmt`가 달라진 것을 감지하고 `post_changed_since_read`로 중단합니다. 사용자는 최신 임시글을 확인한 다음 다음처럼 요청합니다.

```text
사람이 수정한 최신 내용을 유지하면서 아까 제안한 FAQ만 다시 반영해줘.
```

## 시나리오 5: 수정한 글을 이전 상태로 복원하기

**요청 예시:**

```text
방금 수정한 임시글을 수정 전 상태로 되돌려줘.
```

AI는 복원 가능한 스냅샷을 확인하고 대상과 시간을 보여준 뒤 복원 명령을 실행합니다. 복원은 임시글에만 적용되며 복원 직전 상태도 새 스냅샷으로 남습니다.

## 시나리오 6: 여러 SEO 플러그인 환경

- Rank Math가 활성화되어 있으면 Rank Math 필드에 저장합니다.
- Yoast SEO가 활성화되어 있으면 Yoast 필드에 저장합니다.
- AIOSEO가 활성화되어 있으면 AIOSEO 글 모델에 저장합니다.
- 지원 SEO 플러그인이 없으면 WordPress 제목과 요약을 검색 정보의 기본값으로 사용합니다.

사용자는 플러그인 종류를 매번 지정할 필요 없이 프로필에서 `auto`를 선택할 수 있습니다.

## 시나리오 7: Claude Desktop이나 Cursor에서 사용하기

Windows 설치를 마친 뒤 MCP 설정에 `scripts/run-mcp.ps1`을 등록합니다. 이후 다음과 같이 요청합니다.

```text
워드프레스 연결 상태를 확인하고, 문제가 없으면 자동차 보험 갱신 체크리스트 글을 임시저장해줘.
```

Codex와 동일한 안전한 초안 생성, 검사, 복원 기능을 사용합니다. 자동 공개 도구는 MCP에도 제공되지 않습니다.

## 시나리오 8: 여러 블로그를 분리해 운영하기

개인 재테크 블로그와 회사 블로그를 각각 연결한 뒤 다음처럼 요청합니다.

```text
회사블로그 프로필을 사용해서 이번 글을 임시저장해줘. 저장 전 대상 사이트 이름을 계획에서 확인해줘.
```

프로그램은 선택된 사이트의 자격증명과 글쓰기 규칙만 불러옵니다. 저장 전 계획의 `site_profile`과 사이트 주소가 요청과 다르면 중단합니다. MCP에서는 사이트마다 별도 서버 항목을 만들고 `WPDP_SITE` 값을 다르게 지정합니다.

## 시나리오 9: 한 달 콘텐츠 계획 세우기

Search Console에서 검색결과 CSV를 내려받은 뒤 다음처럼 요청합니다.

```text
이 Search Console 파일과 워드프레스 글 목록을 분석해서 앞으로 4주 동안 주 2개씩 쓸 주제를 추천해줘. 부족한 카테고리, 기존 글 보완 여부와 내부 링크 후보도 알려줘. 아직 글을 만들거나 예약하지 마.
```

프로그램은 모든 글과 카테고리를 읽고 Search Console의 노출·클릭률·평균 순위를 합산합니다. 결과의 일정은 `proposal_only`이며 WordPress에는 아무 변경도 하지 않습니다.

## 시나리오 10: 사용 중단과 접근 권한 폐기

1. `uninstall.ps1`로 Codex 스킬을 제거합니다.
2. `-RemoveCredentials` 옵션으로 로컬 암호화 설정과 프로필을 삭제합니다.
3. WordPress 사용자 프로필에서 `WP Draft Publisher` 애플리케이션 비밀번호를 폐기합니다.
4. 더 이상 필요하지 않다면 WordPress 브리지 플러그인을 비활성화하고 삭제합니다.

이 네 단계를 완료하면 로컬 자동화 도구와 WordPress 접근 권한이 모두 제거됩니다.
